# Buffer Uppercut 0.1.0-preview.3

Unsigned preview 3 introduces a redesigned native editor with a cream chassis,
charcoal panels, acid-yellow accents, aligned light performance pads, larger
responsive dials, and a stereo waveform grid. Selected pads have an outline;
held pads light up, and suspended pads use a warm orange state.

All seven effect macros remain accessible beside the effect selector. The
layout supports the 920×620 minimum, the 1120×700 default, and wider windows.
DSP behavior, the 145 host parameters, MIDI mappings, and the kit format are
unchanged from preview 2.

## Downloads and source

- Linux x86-64: CLAP and VST3, built on Ubuntu 22.04.
- Windows x86-64: CLAP and VST3, built on `windows-2022`.
- macOS Apple silicon: CLAP and VST3, built on the arm64 `macos-14` runner.
- Standalone is a development host and is not distributed.
- Source revision: the commit identified by tag `v0.1.0-preview.3` in
  https://github.com/piducancore/buffer-uppercut.

Linux targets glibc-based x86-64 distributions and may require the host's audio,
font, graphics, udev and X11 runtime libraries. Linux has not been tested in a
real DAW; LMMS does not natively host these CLAP/VST3 formats.

## Validation and accepted preview limitations

The redesign passed local formatting, Clippy, workspace and allocation-paranoid
tests, all five deterministic screenshot checks, and CLAP Validator. Local
macOS REAPER checks covered both native editors, pad selection, macro dragging,
effect-default changes, factory navigation and the direct-key toggle.

The release workflow validates the exact tagged CLAP/VST3 bundles on all three
platforms with CLAP Validator and pluginval before packaging them. Dependency
versions and external license texts are unchanged from preview 2.

The exact release ZIPs have not received a complete real-DAW acceptance pass on
all platforms. Earlier macOS/Windows Ableton Live endurance testing used prior
development builds; it does not validate the redesigned editor on those hosts.
This preview accepts those limits. Detailed recorded automation, listening,
CPU, non-US keyboard-layout and GUI acceptance remain open in `docs/TESTING.md`.

These are unsigned previews: Windows Authenticode signing, macOS Developer ID
signing and macOS notarization are absent. Operating systems or DAWs may warn
about or block installation. Follow `INSTALL.txt` inside each package; do not
disable antivirus or system-wide security protections. Use a test project.
`SHA256SUMS` verifies file integrity but is not a publisher signature.
