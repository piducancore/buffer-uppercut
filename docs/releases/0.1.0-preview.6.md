# Buffer Uppercut 0.1.0-preview.6

Build the audio chain as you play: effects now process in pad press order.
Filter then LoFi and LoFi then Filter are different signal paths. Release a pad
to remove it; press it again to append it. The six-processor cap still suspends
the oldest admitted stage, and restored stages retain their original press position.
Presses first observed in the same audio block tie-break by pad number.

The waveform panel shows final stereo output over a faint input reference,
with simultaneous effect visuals, independent buffer cursors, and separate
suspended-stage badges. Stage cards follow the actual audio chain; click one
to select its pad controls.

## State and automation

Parameter IDs, the 144-parameter count, and `.bupreset` version 3 are unchanged.
Existing performances can sound different because routing now follows observed
press order. Unheld buffer slots record final chain output for their next append.
Previously captured audio is retained when upstream stages change.

## Downloads and source

- Linux x86-64: CLAP and VST3, built on Ubuntu 22.04.
- Windows x86-64: CLAP and VST3, built on `windows-2022`.
- macOS Apple silicon: CLAP and VST3, built on the arm64 `macos-14` runner.
- Standalone is a development host and is not distributed.
- Source revision: the commit identified by tag `v0.1.0-preview.6` in
  https://github.com/piducancore/buffer-uppercut.

Linux targets glibc-based x86-64 distributions and may require the host's audio,
font, graphics, udev and X11 runtime libraries. Linux has not been tested in a
real DAW; LMMS does not natively host these CLAP/VST3 formats.

## Validation and accepted preview limitations

Local workspace and allocation-paranoid tests pass (108 tests), with formatting,
Clippy, three editor-size baselines, and CLAP/VST3 builds verified. Tests confirm
opposite press orders produce different audio and release/repress and restoration
preserve the documented ordering. Basic use of the earlier waveform build was
confirmed by the user; exact release artifact listening remains pending.
The release workflow gates packaging on tests, exact-bundle CLAP Validator and
pluginval, and third-party notice inventory checks on all three platforms.

Visualization CPU sign-off remains open: preliminary measurements exceeded the
10% relative regression threshold in some configurations. Press-order sorting
uses a fixed 16-element array once per block, but its incremental CPU cost has
not been separately measured. This preview accepts those limitations for testing;
it is not a stable performance sign-off. Rapid taps within one block can collapse,
and ordering within that block is not preserved. Full DAW automation, save/reopen,
and cross-platform listening acceptance remain pending.

These are unsigned previews: Windows Authenticode signing, macOS Developer ID
signing and macOS notarization are absent. Follow `INSTALL.txt` inside each
package. Use a test project. `SHA256SUMS` verifies integrity, not publisher identity.
